## 1. Scientific Objective & The Anti-Contamination Invariant

In DriftSense v1, the test partition $D_{\text{test}}$ was evaluated during iterative model development (DEC-016), introducing statistical contamination and invalidating out-of-sample claims. 

### The Invariant:
> **$D_{\text{holdout}}$ is strictly quarantined. It shall not be read, preprocessed, fitted, or evaluated by any script, notebook, or model prior to Phase 15.**

Every run manifest generated across Phases 3 through 14 must record and verify:
```json
{
  "holdout_touched": false
}
```
If `"holdout_touched": true` is observed in any run prior to Phase 15, the execution pipeline will abort with exit code `1`.

## 4. Phase 15 Evaluation Protocol & Integrity Verification

When the project reaches Phase 15 (Final Locked Evaluation), the following steps will be executed:
1. **Pre-Flight Manifest Inspection:** Confirm that all previous phase manifests record `"holdout_touched": false`.
2. **One-Time Evaluation:** Run `driftsense evaluate-holdout --protocol docs/v2/evaluation_protocol.md`.
3. **Immutability Lock:** Once $D_{\text{holdout}}$ evaluation begins, code modifications are prohibited. Any discrepancy or negative result must be recorded directly in the final scientific report without hyperparameter re-tuning.
4. **Digest Calculation:** Record SHA-256 hashes of all holdout dataset partitions and predictions in `runs/run_v2_final_holdout/manifest.json`.
