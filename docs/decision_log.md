# DriftSense — Architecture & Design Decision Log

This log records binding architectural decisions, context, rationale, and consequences for the DriftSense project.

---

### DEC-001: Separation of Antigravity (Implementation) and Claude (Architecture)
- **Status**: **ACCEPTED**
- **Date**: 2026-10-19
- **Context**: Autonomous development requires clear governance to prevent scope creep, untested claims, and architectural drift.
- **Decision**: Antigravity serves strictly as the implementation agent adhering to the Phase protocol. Claude acts as the reviewing architect with final authority over phase gates and specification decisions.
- **Consequences**: Antigravity cannot approve its own work or unilaterally make architectural choices without flagging them as `OPEN ITEM`.

---

### DEC-002: Local Development vs. Colab Execution Boundary
- **Status**: **ACCEPTED**
- **Date**: 2026-10-19
- **Context**: The local machine operates on Windows with CPU-only PyTorch and limited training resources; Colab provides standard Linux GPU/TPU environments.
- **Decision**: Local machine is restricted to code editing, documentation, unit testing (`pytest`), formatting (`ruff`), and tiny synthetic smoke tests. All heavy data exploration, model training, hyperparameter optimization, and experiment runs are deferred to Google Colab.
- **Consequences**: No local training commands will be executed. Antigravity prepares self-contained Colab notebooks generating validated `manifest.json` files.

---

### DEC-003: Standardization on FOCUS 1.3 Billing Data Schema
- **Status**: **ACCEPTED**
- **Date**: 2026-10-19
- **Context**: Cloud billing data differs widely across AWS, Azure, and GCP, complicating multi-cloud cost modeling.
- **Decision**: Adopt the FinOps Open Cost & Usage Specification (FOCUS) v1.3 as the standardized target format for all ingested billing data.
- **Consequences**: Data loaders must map raw cloud billing columns into standardized FOCUS dimensions (`ProviderName`, `ServiceName`, `EffectiveCost`, `BilledCost`, etc.).

---

### DEC-004: Decoupling Anomaly Detection from Model Prediction (Counterfactual Residuals)
- **Status**: **ACCEPTED**
- **Date**: 2026-10-19
- **Context**: Traditional thresholding on raw spend fails to account for normal weekly seasonality and growth trends.
- **Decision**: Anomaly detection operates on the *residual* between actual observed spend ($Y_t$) and counterfactual expected spend ($\hat{Y}_t$) generated by a trained forecasting model, supplemented by unsupervised anomaly detectors.
- **Consequences**: Reduces false positives caused by expected recurring spikes (e.g., weekend dips or planned recurring batch jobs).

---

### DEC-005: Strict Chronological Data Partitioning & Leakage Prevention
- **Status**: **ACCEPTED**
- **Date**: 2026-10-19
- **Context**: Time-series models suffer catastrophic evaluation leakage if rolling-window statistics or scalers touch future observations.
- **Decision**:
  1. All train/validation/test splits are strictly chronological.
  2. All rolling-window features exclude the target row $t$.
  3. Feature transformers and scalers are fit strictly on the training partition.
  4. The test set is locked until final benchmark evaluation.
- **Consequences**: Evaluation scores truthfully reflect real-world online forecasting performance.

---

### DEC-006: Controlled Synthetic Fault Injection for Attribution Ground Truth
- **Status**: **ACCEPTED**
- **Date**: 2026-10-19
- **Context**: Real cloud billing datasets rarely contain verified ground-truth labels identifying the exact operational trigger (e.g., specific bad deployment) behind a cost spike.
- **Decision**: Combine real/public billing traces with a deterministic synthetic event generator that injects known operational faults (deployments, autoscaling loops, misconfigurations) into a separate ground-truth label table.
- **Consequences**: Enables objective calculation of Top-1 and Top-3 cause attribution accuracy while maintaining a clear disclaimer that synthetic labels are not real production truth.

---

### DEC-007: Plain-Text Explainability via SHAP + Natural Language Synthesis
- **Status**: **ACCEPTED**
- **Date**: 2026-10-19
- **Context**: Engineering and finance teams require actionable explanations, not just raw mathematical feature importances.
- **Decision**: Use SHAP values to identify top positive cost drivers and feed them into a structured natural language explainer template (e.g., *"Cost increased by ₹36,000 driven primarily by Database scaling (+62%) following deployment event #412"*).
- **Consequences**: Increases system usability and interpretability on the Streamlit dashboard.

### DEC-009: Champion Forecaster Selection (XGBoost with Log-Transform)
- **Status**: **ACCEPTED**
- **Date**: 2026-10-19
- **Context**: Baseline (Seasonal Naive, Moving Average, Exponential Smoothing) vs ML models evaluated on validation partition ($D_{\text{val}}$).
- **Decision**: XGBoost with `log1p` target transformation selected as champion forecaster (Run `run_20261019_172039_9dc09a`). Achieved WAPE of 59.98% (57% reduction over Seasonal Naive) and MASE of 0.3350.
- **Consequences**: Point residuals $e(t) = y(t) - \hat{y}(t)$ provide a calibrated foundation for Phase 7 anomaly detection.

### DEC-010: Champion Anomaly Detector Selection (Rolling Threshold)
- **Status**: **ACCEPTED**
- **Date**: 2026-10-19
- **Context**: Statistical (Z-Score, Rolling Threshold) vs ML unsupervised (Isolation Forest, One-Class SVM) evaluated on dual-track validation.
- **Decision**: Rolling Threshold Detector selected as champion (Run `run_20261019_174627_660563`). Achieved 0.10% False Positive Rate on real data track, Event-F1 of 0.9219 (59/67 detected, 0.00h mean delay) on synthetic ground truth.
- **Consequences**: Provides low-noise, responsive alerts with robust diurnal tracking.

### DEC-011: Root-Cause Attribution Champion Selection (Temporal Correlation & XGBoost)
- **Status**: **ACCEPTED**
- **Date**: 2026-10-19
- **Context**: 4 attributors (Random, Empirical Class Prior, Temporal Correlation Heuristic, XGBoost Multi-Class Ranker) evaluated on 27 validation incidents with concurrent benign decoy deployments.
- **Decision**: Temporal Correlation Attributor and XGBoost Attributor both achieved 100.0% Top-1, Top-2, and Top-3 accuracy on validation incidents (Run `run_20261019_181013_7bab3d`), effectively rejecting benign background decoy operations. Temporal Correlation selected as primary champion for transparent, zero-hyperparameter interpretability, with XGBoost preserved for multi-modal telemetry jumps.
- **Consequences**: Feeds directly into Phase 9 (Explainability / SHAP) and Phase 10 (Interactive FinOps Dashboard).

### DEC-012: Explainability Engine & TreeSHAP Verification (TreeSHAP with Stability & Non-Causal Narratives)
- **Status**: **ACCEPTED**
- **Date**: 2026-10-19
- **Context**: Model explainability required for the champion forecaster and anomaly explanations under FinOps FOCUS standard, requiring mathematical additivity (A9.1), rank stability across random seeds, and non-causal executive audit reporting (A9.2) without test data leakage (A9.3).
- **Decision**: TreeSHAP explainer implemented and verified on Colab (Run `run_20261019_185103_26be50`). Additivity verified on all 4,983 validation records. Seed stability across 3 runs achieved mean Spearman $\rho = 0.9044$ and Kendall $\tau = 0.7707$. Global drivers identify `BilledCost` (49.67%), `ConsumedQuantity` (7.35%), `EffectiveCost_roll_mean_168h` (4.92%), `day_of_month` (3.99%), and `hour_of_day` (3.55%). Non-causal audit narratives generated with strict association phrasing.
- **Consequences**: Clears all requirements for Phase 9 and provides foundational explanation capabilities for Phase 10 controlled experiments and Phase 11 interactive dashboard.

### DEC-014: Interactive FinOps Streamlit Dashboard Acceptance
- **Status**: **ACCEPTED**
- **Date**: 2026-10-20
- **Context**: Phase 11 requires an interactive FinOps dashboard built with Streamlit adhering to FOCUS 1.0/1.3 standards. Governed by G3 (lightweight local execution, zero in-app training, GPU-free), A11.1 (graceful handling of missing/corrupt artifacts with loader unit tests), A11.2 (smoke validation across all views), and A11.3 (no hardcoded absolute paths, portable run discovery). All dashboard text must strictly use non-causal phrasing ("likely associated causes", "model evidence"). Quarantined test partition ($D_{\text{test}}$, Days 25–30) must remain strictly quarantined.
- **Decision**: Implemented modular Streamlit dashboard in `app/`:
  - `app/loaders.py`: Resilient discovery and ingestion of pipeline artifacts from `runs/` (or via `--run-dir`), returning typed structures and handling missing/corrupt files gracefully.
  - `app/views/overview.py`: Executive Overview with FOCUS KPIs (Clean Spend, Synthetic Injected Spend, Total Anomaly Delta, Run Provenance matrix).
  - `app/views/forecast_anomalies.py`: Time-series forecasting and rolling threshold anomaly alert inspection with per-service filtering.
  - `app/views/attribution.py`: Root-cause attribution view displaying operational drivers with strict non-causal terminology.
  - `app/views/explainability.py`: TreeSHAP global driver bars and executive audit narratives.
  - `app/views/ablations.py`: 7-arm ablation comparison table with empirical variance reporting and synthetic event circularity caveat (A10.3).
  - `app/main.py`: Streamlit entrypoint with dark executive theme and navigation sidebar.
  - `docs/dashboard.md`: Complete architecture and operator guide.
  - `tests/test_app_loaders.py`: 8 unit tests covering normal discovery, missing directories, corrupt JSON/CSV files, and no hardcoded absolute paths (101 total unit tests passing in pytest).
- **Consequences**: Clears all acceptance criteria for Phase 11 (A11.1, A11.2, A11.3). Unblocks Phase 12 (Integration, Packaging, and QA).
